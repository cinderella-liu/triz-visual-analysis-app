# TRIZ 可视化分析工具 APP 需求文档

## 1. 产品定位

TRIZ 可视化分析工具是一款面向产品经理、研发工程师、创新顾问和学习者的移动端分析工具。用户输入一个问题、产品缺陷、系统矛盾或改进目标后，APP 将引导用户用 TRIZ 方法完成结构化分析，并输出清晰的理论分析图谱。

产品重点不是简单展示 TRIZ 知识库，而是帮助用户把一个真实问题转化为可分析、可比较、可推演的创新问题模型。

## 2. 核心目标

1. 帮助用户快速记录和拆解一个待解决问题。
2. 将问题转化为 TRIZ 常用分析对象：系统、组件、功能、矛盾、资源、理想解。
3. 输出可视化图谱，展示问题从现象到矛盾、从矛盾到原理、从原理到方案的推理路径。
4. 保持界面简洁明了，降低 TRIZ 理论的学习门槛。

## 3. 目标用户

### 3.1 入门学习者

想理解 TRIZ 理论，但不熟悉矛盾矩阵、物场分析、九屏幕法等工具。需要模板化引导和示例。

### 3.2 产品与研发人员

面对实际产品问题，需要快速分析问题根因、技术矛盾、资源利用方式和可能的创新方向。

### 3.3 创新咨询与培训人员

需要将分析过程可视化，便于在会议、课程或工作坊中讲解和复盘。

## 4. 核心使用场景

### 4.1 问题捕获

用户输入一句自然语言问题，例如：

```text
如何让手机电池续航更长，同时不增加机身厚度？
```

系统识别：

- 改善目标：续航更长
- 受限条件：不增加机身厚度
- 潜在矛盾：能量容量 vs 体积/重量

### 4.2 TRIZ 分析向导

用户通过分步表单补充：

- 当前系统是什么
- 主要功能是什么
- 哪个指标需要改善
- 哪个指标因此恶化
- 可用资源有哪些
- 期望的理想结果是什么

### 4.3 理论分析图谱生成

系统生成一张结构化图谱：

```text
问题描述 -> 系统模型 -> 功能关系 -> 矛盾识别 -> TRIZ 原理推荐 -> 方案假设
```

图谱节点可以点击查看详情，边表示推理关系。

### 4.4 方案沉淀

用户可以把推荐原理转化为自己的方案草稿，并保存到案例库。

## 5. 功能需求

### 5.1 首页

首页采用简洁工作台布局，突出三个入口：

- 新建分析
- 我的案例
- TRIZ 方法库

首页显示最近分析的案例卡片，包括标题、问题类型、更新时间和图谱状态。

### 5.2 新建分析

支持用户通过文本输入创建一个分析案例。

字段：

- 案例标题
- 问题描述
- 行业/场景
- 当前系统
- 期望目标

MVP 阶段先支持手动输入和本地保存。后续版本再加入 AI 自动抽取。

### 5.3 问题拆解

将一个问题拆为以下结构：

- 现象：用户观察到的问题
- 目标：用户希望改善的指标
- 限制：不能恶化或不能改变的条件
- 对象：涉及的系统、子系统、组件或环境
- 初步假设：可能的原因或矛盾

### 5.4 矛盾分析

支持两类矛盾：

- 技术矛盾：改善一个参数会导致另一个参数恶化
- 物理矛盾：同一对象需要同时具备相反属性

用户可以从参数列表中选择，也可以手动输入。

输出：

- 矛盾描述
- 改善参数
- 恶化参数
- 推荐创新原理
- 推荐理由

### 5.5 TRIZ 方法库

内置基础方法：

- 40 个发明原理
- 技术矛盾矩阵
- 物理矛盾分离原理
- 九屏幕法
- 资源分析
- 理想最终结果 IFR
- 物场分析

MVP 阶段优先实现：

- 40 个发明原理浏览
- 矛盾分析
- 九屏幕法基础模板
- 资源分析模板

### 5.6 图谱输出

图谱是产品的核心输出。

节点类型：

- 问题节点
- 系统节点
- 组件节点
- 功能节点
- 矛盾节点
- 原理节点
- 方案节点

边类型：

- 属于
- 影响
- 导致
- 改善
- 恶化
- 推荐
- 转化为

图谱交互：

- 缩放
- 拖拽节点
- 点击查看详情
- 展开/收起分支
- 导出图片

MVP 阶段图谱可以先用固定布局：从左到右展示“问题 -> 矛盾 -> 原理 -> 方案”。

### 5.7 案例库

用户可以保存多个分析案例。

每个案例包含：

- 标题
- 问题描述
- 分析状态
- 矛盾列表
- 推荐原理
- 方案草稿
- 图谱数据
- 创建时间
- 更新时间

### 5.8 导出

支持导出：

- PNG 图谱
- Markdown 分析报告
- JSON 图谱数据

MVP 阶段优先支持 Markdown 报告和 PNG 图谱。

## 6. 非功能需求

### 6.1 界面风格

设计风格：简洁、清晰、理性、低干扰。

建议视觉方向：

- 主色：深蓝或墨绿色，用于表达理性和工程感
- 辅色：琥珀色或青色，用于强调矛盾与推荐路径
- 背景：浅灰白
- 卡片：低圆角、轻边框、少阴影
- 字体：层级清楚，避免大面积装饰性排版

### 6.2 移动端体验

- 首页一屏内展示核心入口
- 表单分步填写，避免一次性展示过多字段
- 图谱默认适配竖屏，支持横屏查看
- 节点文字不能互相遮挡
- 关键操作固定在底部工具栏

### 6.3 数据存储

MVP 阶段使用本地存储，保证离线可用。

后续版本可增加：

- 云同步
- 多设备同步
- 团队共享案例库

## 7. MVP 范围

第一版可交付能力：

1. 新建 TRIZ 分析案例。
2. 手动填写问题、目标、限制和矛盾。
3. 选择或推荐 40 个发明原理。
4. 生成基础理论分析图谱。
5. 保存案例到本地案例库。
6. 查看、编辑、删除历史案例。
7. 导出 Markdown 分析报告。

暂不做：

- 完整 AI 自动分析
- 团队协作
- 云同步
- 复杂自由布局图编辑器
- 全量 TRIZ 专家系统推理

## 8. 版本规划

### V1：TRIZ 案例收件箱

目标：先让用户能记录问题，并形成案例库。

功能：

- 新建案例
- 本地保存
- 案例列表
- 基础字段编辑
- 中文界面

### V2：矛盾分析向导

目标：让用户能把问题转化成 TRIZ 矛盾模型。

功能：

- 技术矛盾表单
- 物理矛盾表单
- 改善参数/恶化参数选择
- 推荐发明原理
- 矛盾卡片展示

### V3：图谱输出

目标：让产品真正“可视化”。

功能：

- 问题到方案的分析图谱
- 节点详情面板
- 图谱缩放和拖拽
- PNG 导出

### V4：AI 辅助分析

目标：降低手动建模成本。

功能：

- 自动抽取问题要素
- 自动识别潜在矛盾
- 自动推荐 TRIZ 工具
- 自动生成分析报告草稿

### V5：案例复盘与知识库

目标：让工具从单次分析变成长期知识资产。

功能：

- 案例标签
- 行业模板
- 方案效果记录
- 相似案例检索
- 团队案例库

## 10. 关键验收标准

1. 用户可以在 1 分钟内创建一个 TRIZ 分析案例。
2. 用户可以清楚看到问题、矛盾、原理、方案之间的关系。
3. 图谱在手机竖屏下可读，不出现严重文字重叠。
4. 用户可以保存并再次打开历史案例。
5. 用户可以导出一份可阅读的 Markdown 分析报告。

## 11. 推荐下一步

建议不要直接做完整专家系统。下一步先做 V1：TRIZ 案例收件箱。

理由：

- 可以复用当前 Voice Flow OS 已经做通的本地任务收件箱能力。
- 用户体验路径最短：先把问题收进来，再逐步做分析。
- 后续可以自然扩展成矛盾分析、图谱生成和 AI 辅助。

建议第一个开发任务：

```text
[TRIZ 可视化工具] 新建独立 APP 原型，支持创建、保存和查看 TRIZ 分析案例。
```
